# 运行状态与资金费率同步观测设计

## 状态、依据与范围

用户在本会话对“状态页面 + 状态查询 API + 健康检查 + 现有结构化日志”明确答复“好的，落实”，授权实现该范围。本文记录这一确认及其常规实现细节；按该授权连续完成实现与验证。

本设计只扩展运行状态观测。它替代 `2026-09-06-funding-rate-history-sync-design.md` 中“不提供页面/HTTP 查询”的限制，其余发现、分页、覆盖证明、重试、事务、交易隔离和错误证据规范继续生效。不提供数据导出、手动同步、配置修改、指标平台或外部告警。

## 方案选择

采用现有 Fastify + 静态页面，同进程读取 repository 的严格状态对象；已有 funding events 同时更新内存观测快照和输出日志。完整覆盖当前需要，不引入依赖、持久表或新的业务状态机。

直接使用 SQLite 工具能查看持久状态，但独占锁要求停机，无法满足在线查看。独立 Prometheus/Grafana 可以观察趋势，但仍需业务状态接口，并增加部署和维护流程；当前没有跨进程指标需求。

## API 与生命周期

- `GET /health/live`：200 表示 HTTP 进程可响应，不访问数据库、交易所或账户。
- `GET /health/ready`：仅服务已启动且现有 SQLite 连接的 `SELECT 1` 成功时为 200；尚未启动、正在关闭、已关闭或数据库检查失败为 503，并给出具体阶段或脱敏原因。它不承诺交易所可用、预检通过或资金同步完整。
- `GET /api/status`：返回生成时间、服务阶段、服务运行时长、数据库检查、同步调度间隔、同步器生命周期、最近 fatal、两交易所本进程最近发现结果和市场持久状态。状态读取失败返回现有结构化 HTTP 错误，不返回空数组冒充健康。
- `GET /status.html`：独立只读中文页面，首页有入口。复用现有样式、Host 检查、CSP、错误处理和逐请求日志。API/health 响应禁止缓存。

服务阶段由 `startService` 在监听与同步启动完成后标记 RUNNING，在 shutdown 开始、等待任何后台任务之前标记 STOPPING，资源关闭后标记 STOPPED。资金 fatal 只影响资金同步展示，不改变交易服务 readiness。进程存活与资金采集健康独立展示。

`service.startedAt` 为首次进入 RUNNING 的时间；此前为 null，`uptimeMs` 为 0，不把构造与等待监听计入运行时长。

同步器事件状态从 NOT_STARTED 到 RUNNING；fatal 记为 FAILED，后续 stopped 不能抹掉 fatal。发现结果显示 NEVER/SUCCEEDED/INCOMPLETE、最近结束时间、最近成功时间、数量和完整脱敏错误证据；内存信息重启后重置，页面明确说明。不凭没有事件推测请求当前处于何阶段。

## 市场状态与展示口径

按交易所和市场排序，从 `listMarketStates` 读取所有已知市场，明确区分 active/inactive，保留 coverage 与 incremental 两套状态和计数。展示市场标识、重新激活待复核、最近启动/结束/成功时间、coverage generation、cutoff、lastCaughtUpCutoffMs、最早/最新已入库结算时间和两套失败码/原因。

计数按持久状态统计，BACKFILLING/RUNNING 是数据库任务记录，不证明该任务正在当前进程执行。页面写明这一点。CAUGHT_UP 只证明接口可见范围至对应截止时间，不能用最新记录时间或增量成功替代。空市场列表显示尚无已知市场，并保留发现结果，不能宣称全部完成。不计算不可靠的历史百分比、下一次执行时间或未证实的过期阈值。

页面每 10 秒查询一次，提供手动刷新与交易所/市场搜索；请求串行，10 秒超时。刷新失败显示当前失败，保留最后成功快照并明确标记已过期；持续失败时不继续显示当前健康。动态文本使用 textContent，错误详情可展开，不注入 HTML。页面停止或隐藏时停止轮询，恢复可见时刷新。

主动暂停导致的请求取消不显示网络失败；若恢复时旧请求仍未结束，记下待刷新意图，旧请求结束后立即重新请求。客户端验证所有被渲染状态的枚举、时间、错误证据，以及计数与市场列表、fatal 与同步器状态、readiness 与服务阶段的一致性；无效响应不得替换最后可信快照。

## 安全与可测试性

- 状态读取只使用已有连接，不建立第二连接、不扫描历史记录、不触发交易所请求、不写业务数据。
- 明确投影公开字段；正常快照不返回原始响应、credentials、环境变量或数据库路径配置，公开错误不返回堆栈。错误原因链和远端证据保留；返回边界再次按既有凭证规则脱敏，包括持久错误文本。
- 观测不改变事件日志行为，日志 sink 失败不影响状态采集与同步。
- 时间戳后缀 Ms 为 Unix 毫秒；ISO 时间为 UTC，页面明确显示 UTC。
- 全部验证使用 fake gateways/sources、内存或临时 SQLite 和临时环境值，绝不运行生产入口或读取真实 `.env`/业务数据库。

审查修订依据：合法数据库文件名可以是 `a` 或 `api`，把它加入通用 substring 秘密集合会破坏市场身份、`/api/status` 请求路径和普通错误文字。数据库文件路径本身不是凭证，失败诊断中的必要文件路径保留为定位证据，遵循既有 code-rules 与 fail-fast-with-evidence；这替代了初稿将所有错误路径一并隐藏的要求，不改变任何凭证脱敏规则。

## 验收

1. 操作员可以在服务运行时查看状态，首页可达；正常、空状态、同步失败和刷新失败均有明确展示。
2. live/ready 语义与生命周期一致，shutdown 在等待后台任务时已经不就绪；资金失败不被误报为 HTTP 服务死亡。
3. 持久状态和当前进程观测分别标识，coverage/incremental 不相互覆盖，重启不伪造发现成功。
4. 返回和页面无敏感值、堆栈或 HTML 注入；新入口保留既有访问和日志边界。
5. 定向测试、全量测试、静态构建和使用假数据的浏览器检查通过。
